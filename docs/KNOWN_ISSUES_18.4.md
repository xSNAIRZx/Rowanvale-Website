# Known limitations — Rowanvale 18.4.0 RC

- Live TMDB and IGDB authentication could not be exercised because no credentials were supplied. Their request mapping, errors, rate handling and credential separation were tested with controlled provider responses. Users must configure their own credentials and permitted terms.
- Live Open Library search, work synopsis and a selected cover download were verified. Provider completeness, uptime and image availability still vary. Optional Steam and pre-existing unrelated external services were not live-certified.
- AniList is disabled under its tracker restrictions. Anime uses animated TMDB television results when configured; manga lookup and comprehensive anime-specific relationships are not implemented.
- Google Books, SteamGridDB and RAWG in the new unified matcher are optional integrations left out of this release. The old RAWG-backed game directory is retained.
- Cross-format suggestions use shared genres/tags. The included verified relationship example is the Witcher franchise, with a publisher source; this is not an exhaustive adaptation/franchise graph. Similarity is never presented as a verified adaptation.
- Reminder prompts appear while the Sessions page is open. This release does not send operating-system push notifications or monitor activity outside Rowanvale. Closing the app preserves the session start time; correct idle minutes when finishing.
- Maintenance queue previews live in memory and reset on reload. The user's library and approved changes persist. Batches are deliberately limited to twelve stories; retries are user-triggered and providers may impose additional cooldowns.
- Metadata response caches are bounded and in memory. Explicitly saved metadata persists with the library. Offline covers require a permitted selected download or a custom upload. The browser keeps up to 80 recently requested selected private covers; the server retains its larger existing disk cache. Disk covers require an artwork ZIP backup when moving computers.
- The app uses browser storage. It does not add a new encrypted account service, hosted social syncing or cross-device automatic synchronization. Existing optional integrations are preserved and need their own setup.
- Historical achievements remain in history after activity corrections. Historical 18.3 XP is preserved, including balances whose older event details had already been discarded by 18.3. Missing old events cannot be recovered from application source.
- Self-reported progress is not externally authenticated. Per-event duplicate protection, 300 daily repeatable XP and 750 daily overall new XP ceilings constrain repeated awards; this is a private personal progression system, not an anti-cheat service for public competition.
- Browser verification used installed desktop Chrome, including 390/768/1440px viewports, light/dark themes, keyboard interactions and offline startup. This is not a physical-device, screen-reader, Safari or every-browser certification. The historical Python harnesses were not executed in this Windows environment; their key media workflows were covered by the new Node browser regression tests.
